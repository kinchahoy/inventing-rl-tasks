# Real machine inventory: dual-accelerator inference workstation (host label `mi60-server`)

Read-only exploration, 2026-11-03, unprivileged (`sudo -n` needs an interactive password). Secrets redacted. Real details live only in this directory and the recipe's `provenance.md`.

## Identity
- Ubuntu 26.04.1 LTS ("Resolute Raccoon"), kernel `7.0.0-38-generic`, x86_64, desktop board (ASUS Z890, Intel Arrow Lake CPU with iGPU) in a desktop chassis, headless (multi-user.target default; GUI stack absent).
- Two AMD Instinct MI50/MI60 32 GB cards (Vega 20, gfx906) at PCI `03:00.0` and `87:00.0`; Intel iGPU `00:02.0`. NVMe 3.7 TB: ESP + one Btrfs with subvolumes `@ @home @var @snapshots` (`compress=zstd:3,noatime,discard=async`, fstab uses plain `compress=zstd,noatime`; `/.snapshots` is `relatime`, no compress option in fstab).
- Role: private LLM inference box (llama.cpp built against a pip-installed ROCm SDK), suspended when idle and woken on demand, monitored by a metrics agent.
- Operator is the only login (uid 1000), groups: adm, sudo, video, render (992), kvm (993), i2c (113), docker (987).

## Sleep / suspend (the heart of the machine)
- `/etc/systemd/logind.conf` (main file edited, not a drop-in): `[Login] IdleAction=suspend`, `IdleActionSec=4h`. `sleep.conf` untouched; no `sleep.conf.d`.
- `hibernate.target` and `hybrid-sleep.target` are symlinks to `/dev/null` in `/etc/systemd/system` (masked); `suspend`, `suspend-then-hibernate`, `sleep` static. `/sys/power/state: freeze mem disk`, `mem_sleep: s2idle [deep]`.
- `/etc/systemd/system/sleep.target.d/VR-gpu-cleanup.conf`: `[Unit] Requires=VR-gpu-sleep-cleanup.service After=VR-gpu-sleep-cleanup.service`.
- `VR-gpu-sleep-cleanup.service` (custom): `DefaultDependencies=no`, `Before=sleep.target`, `PartOf=sleep.target`, `Type=oneshot`, `RemainAfterExit=yes`, `TimeoutStartSec=90s`, `TimeoutStopSec=30s`, `ExecStart=/usr/local/bin/VR-gpu-sleep-cleanup.sh`, **`ExecStop=/usr/local/bin/VR-gpu-init.sh`** (stopping the unit on resume re-applies power caps). The script finds PIDs holding `/dev/kfd` open via `/proc/*/fd`, stops their system units / Docker containers, SIGTERMs (10 s grace) then SIGKILLs the rest, and exits 1 ("refusing suspend") if any remain, which blocks the suspend. Env-overridable binaries (`KFD_DEVICE`, `PROC_ROOT`, `DOCKER_BIN`, …).
- `VR-idle-check.timer` (`OnBootSec=5min`, `OnUnitActiveSec=5min`) -> `VR-idle-check.service` (`Type=oneshot`, `After=network.target`) -> `/usr/local/bin/VR_idle_suspend.sh`: takes a flock, counts established non-loopback TCP connections (`ss -Htnp state established`) minus ports 67/68 and processes `tailscaled`/`beszel-agent`, sums `gpu_busy_percent` for both cards by PCI address, compares 1-min load to 2.0, and runs `systemctl suspend` only after `IDLE_LIMIT=2` consecutive idle runs (counter in `/tmp/network_idle_counter`). Any read failure resets the counter ("fail towards awake").
- `VR-gpu-setup.service` (custom, enabled, `Type=oneshot`, `RemainAfterExit=yes`) runs `/usr/local/bin/VR-gpu-init.sh`: for PCI `0000:03:00.0` and `0000:87:00.0` writes `power/control=on` and `hwmon/hwmon*/power1_cap` = **210000000** and **170000000** µW (asymmetric, addressed by slot so enumeration order cannot swap them; read-back verified), sets `energy_performance_preference=power` on every CPU, and blanks RGB LEDs with OpenRGB (errors ignored). Two earlier versions are kept as `VR-gpu-init.sh.pre-mi60-200w-…` / `…210w-…` (dated backups with older caps: decoys). **Currently in `failed` state** (since 2026-10-29: "power cap file not found for GPU 0000:03:00.0", i.e. the hwmon was not ready at boot — a race), yet the live cap read back as 210000000.
- A third unit, `mi60-lab-revoke-on-boot.service` (ConditionPathExists on a sudoers drop-in) and `/usr/local/sbin/mi60-lab-control` (status/gpu-cap/fan-fixed/fan-profile/restore/expire/revoke) belong to the temporary lab-access mechanism, not the server's role. Intentionally excluded from the replica.
- `/usr/lib/systemd/system-sleep/`: distro `fancontrol`, `hdparm`, `sysstat.sleep`, `unattended-upgrades`. No operator hooks.
- `fwupd-refresh.service.d/override.conf` (After/Wants `default.target`, `Type=idle`, forced refresh), `sysstat-collect.timer.d/override.conf` (`OnCalendar=` reset then `*-*-* *:*:00`, i.e. every minute).

## Assessment

Replicability in a VM: **good for configuration, none for hardware.**
- Pure configuration, expressible on a VM and checkable by effective state: `/proc/cmdline` tokens, `modprobe -c` (options/install/blacklist), `/proc/sys` (lockup/hung-task values, softlockup left default), masked sleep targets (`systemctl is-enabled`), `logind` IdleAction via D-Bus, `sleep.target` Requires/After drop-in, the cleanup unit's properties (including **ExecStop re-applying caps**), the idle timer + script behaviour (journal says "Not idle" while an SSH session is up), service enabled/disabled state, `LimitNOFILE`, the hardened metrics agent, uv project files and the wrapper.
- Needs real hardware: the cards, `/dev/kfd`, `power1_cap`/`gpu_busy_percent` sysfs files, DKMS, kdump, iTCO watchdog, an actual suspend. The draft substitutes a fixture directory with regular files for sysfs and a recording stand-in for `systemctl suspend`. Documented in the task provenance.
- Trickiness: **high**, in the style of `author/complexify.md`: (1) cloud/distro images override `GRUB_CMDLINE_LINUX_DEFAULT` so a drop-in must append and a reboot is needed to see it; an abandoned `.cfg.disabled` profile is an inert decoy; (2) `install … /bin/false` vs `blacklist` semantics, `options` for a module not loaded; (3) main-file logind edit vs drop-ins; (4) masked targets as `/dev/null` symlinks (Nix: `enable = false`); (5) `PartOf`/`Before` + `ExecStop` doing the resume work; (6) asymmetric per-PCI-slot caps; (7) installed-but-disabled service; (8) sysstat timer list-reset override; (9) wrapper script vs symlink and explicit-index uv project; (10) doc drift (README cmdline, python version) means the reference must be read, not the notes.
- Sensitivity: operator documents and shell history are full of personal content; none copied.

Verdict: **chosen for the draft task `node37-reconstruction-hard`.**

## Systemd custom-unit survey (addendum, read-only)

Non-distro unit files in `/etc/systemd/system`: `VR-gpu-setup.service`, `VR-gpu-sleep-cleanup.service`, `VR-idle-check.{service,timer}`, `VR-llama-server.service`, `beszel-agent{,-update}.service`, `beszel-agent-update.timer`, `mi60-lab-revoke-on-boot.service` (lab access, excluded), `itco-watchdog-load.service`, drop-ins `sleep.target.d/VR-gpu-cleanup.conf`, `sysstat-collect.timer.d/override.conf`, `fwupd-refresh.service.d/override.conf`, plus snap mounts. No user units (`~/.config/systemd/user` empty, `systemctl --user` shows only devices). No drop-ins on the VR-* units themselves (`DropInPaths` empty).

Effective ordering (`systemctl show`):
- `sleep.target`: `Requires=VR-gpu-sleep-cleanup.service`, `After=VR-gpu-sleep-cleanup.service`, `Before=systemd-suspend.service systemd-suspend-then-hibernate.service grub-initrd-fallback.service`, `RequiredBy=systemd-suspend*.service`. Result: a failing cleanup (exit 1 when `/dev/kfd` holders survive SIGKILL) fails `sleep.target`, so the suspend job fails and the machine stays up.
- `VR-gpu-sleep-cleanup.service`: `PartOf=sleep.target`, `Before=sleep.target`, `RequiredBy=sleep.target`, `DefaultDependencies=no` (hence no `Conflicts=shutdown.target`), `UnitFileState=static` (no [Install]); stays active (RemainAfterExit) through the sleep; when `sleep.target` stops after resume, PartOf propagates the stop and `ExecStop=VR-gpu-init.sh` re-applies caps.
- `VR-gpu-setup.service`: default dependencies; `WantedBy=multi-user.target`, `Before=mi60-lab-revoke-on-boot.service multi-user.target`; **not ordered after any GPU/hwmon readiness**, hence the observed boot race; it was also not re-run after resume except via the cleanup unit's ExecStop.
- `VR-idle-check.timer` -> `.service` (`After=network.target`, static, only triggered by the timer; `Type=oneshot`, `Environment=PATH=…` set explicitly because the script uses bare `flock`, `awk`, `sed`).
- `coolercontrold.service` (package unit, `Type=notify`, `WatchdogSec=30`, `Restart=always`) is a fan/LED controller; ordered before the lab-revoke unit. `gpu-manager.service` (Ubuntu PRIME helper) and `thermald`, `lm-sensors`, `fancontrol` (enabled but no config) are enabled distro units.
- `beszel-agent-update.timer`: `OnCalendar=daily`, `Persistent=true`, `RandomizedDelaySec=4h`; the service is `Type=oneshot`, `Wants=beszel-agent.service`, `ExecStart=… update`. `beszel-agent.service` is `WantedBy=` both `multi-user.target` and the update service (a reverse `WantedBy`, caused by `Wants=` in the update unit being pulled into `[Install]` in practice: observed in `WantedBy`).
- Interaction with the compute stack: `VR-llama-server` (disabled) holds `/dev/kfd` when started; if a user starts it by hand, the cleanup script will `systemctl --no-block stop` it before suspend (system unit holders other than docker.service), stop containers by cgroup ID, then TERM/KILL. The venv-installed ROCm SDK (user-space) is the only thing that opens `/dev/kfd`; the kernel parameters (`amdgpu.gpu_recovery=1`, `noretry=1`, `aspm=0`) affect resume stability, and the hung-task/hardlockup panic sysctls convert a stuck resume into kdump + reboot after 30 s.
